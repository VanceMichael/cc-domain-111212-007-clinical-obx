# 来源格式与业务语义

仅支持来源约定 ORU^R01 子集。MSH-1 字段分隔符在第 4 字符，MSH-2 依次定义组件、重复、转义、子组件（四个互异字符）。解析按 MSH 声明的分隔符进行，不写死 `|^~\&`。转义序列 `F/S/T/R/E` 分别还原为字段、组件、子组件、重复、转义字符本身；高亮标记 `H/N` 属来源约定外的排版信息，予以剥离；未识别转义原样保留并在 notes 留证，不猜测含义。OBR-2 是申请号；OBX-2 类型 NM/ST/CE，OBX-3 代码含编码系统，OBX-4 子观察号，OBX-5 值，OBX-11 状态 F/C/D。D 精确撤销该复合观察，不删患者。空与协议空值标记分开。所有患者和实验室均为虚构，不处理真实医疗指导。

OBX-2 决定 OBX-5 的解释方式：NM 解释为数值（非法数值隔离并给出原因），ST 解释为反转义文本，CE 解释为含编码系统的结构化编码，未知类型隔离到对应观察但保留报文上下文。OBX-5 的每个重复分隔符片段是同一观察下的独立类型化值，保留为 `values` 数组，不拼接成字符串；OBX-4 子观察号不同则是不同观察。OBX-6 单位与 OBX-7 参考范围原样留证，无明确换算配置时不做单位换算。观察复合身份、幂等、更正/撤销版本规则及“为什么不能按段号或患者号去重”见 `observation-identity.md`。

本地演练夹具由 `sampledata.py` 生成，均为虚构业务数据。`sample` 是当前可查看输入，`invalid` 是边界失败输入，其余用于对照来源变体。生成不会下载资源。

本地 HTTP 演练器采用方法与原始路径作为路由键，值为按调用次数返回的响应数组，耗尽后维持最后一项。响应可定义 status、headers、text/base64、require_headers、chunk_bytes、disconnect_after。每次请求保留方法、路径、头与正文摘要表示，便于核对实际访问；演练器只监听回环地址。

原始输入上限 16 MiB 是现有查看入口的保护值，不代表未来持续采集需一次读完整来源。格式含义和截断错误不能被 HTTP 200 覆盖。
