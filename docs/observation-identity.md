# 观察身份、版本与去重约定

本文件说明类型化采集如何确定“同一个观察”，以及为什么不能按 HL7 段号或
患者号去重。所有数据均为本地虚构患者与机构。

## 观察的复合身份

一个观察由以下五个字段共同确定，缺一不可：

| 组成 | 来源 | 含义 |
| --- | --- | --- |
| 发送机构 `sending_facility` | MSH-4 | 合作实验室不同，同一项目编号也可能指不同口径 |
| 申请单号 `order_number` | OBR-2 | 同一患者可多次申请，申请单之间结果互不复用 |
| 项目编码系统 `coding_system` | OBX-3 第 3 组件 | 同一标识符在不同编码系统中含义不同 |
| 项目标识符 `identifier` | OBX-3 第 1 组件 | 检验项目代码 |
| 子观察号 `sub_id` | OBX-4 | 同一项目的不同子观察（如培养的不同菌种） |

`identity_key` 是这五字段按固定顺序的拼接，仅用于库内唯一约束，展示时
仍以结构化字段输出。患者标识（PID-3 合成号）只用于检索关联，**不参与
观察身份**；患者姓名（PID-5）在解析层即不采集，查询界面不展示任何姓名。

## 为什么不能按段号去重

HL7 段顺序号（第几个 OBX）只是报文内的临时位置，不是业务身份：

* 同一份报文增删一个项目后，后续 OBX 的段号整体平移，段号相同的两个
  OBX 可能毫无关系。夹具 `other_order.hl7` 与 `sample.hl7` 都使用
  `OBX|1` 和相同的 `GLU^Glucose^L` 项目，但分属 `order-1` 与 `order-9`
  两张申请单，必须作为两个观察并存（见
  `tests/test_repository.py::test_segment_number_cannot_deduplicate_observations`）。
* 自定义分隔符、重复值（一个 OBX 含多个 OBX-5 重复）都会让“一个段”与
  “一个结果”不再一一对应；段号无法表达重复值内的第 n 个值，也无法表达
  同一项目的子观察号。

因此段号只保留在版本记录的 `segment_index`/`raw_segment` 中用于回溯
报文位置，绝不参与唯一约束。

## 为什么不能按患者号去重或撤销

患者号标识的是人，不是某一次检验结果：

* 同一患者会有多张申请单、多个项目、多次复查。按患者号去重会让新结果
  覆盖历史结果，按患者号撤销会删除该患者的全部结果。
* 撤销（OBX-11 = D）必须精确作用于复合身份指向的那一个观察。夹具
  `subid_cancel.hl7` 只撤销 `CULT` 项目子观察号 `2`，同一项目子观察号
  `1` 以及该患者其他项目保持不变（见
  `test_cancel_targets_only_the_sub_observation`）。
* 撤销不删除数据：被撤销观察保留全部历史版本，状态置为 `cancelled`，
  旧值仍可通过 `history` 回溯。

## 重复值与子观察号的区别

* **重复值**（OBX-2 定义的重复分隔符，标准为 `~`）：同一个 OBX 字段内
  同一观察的多个并列值，属于同一个观察身份，解析为该观察 `values`
  数组中的多个类型化值，不能拼成一个字符串。
* **子观察号**（OBX-4）：不同的观察，拥有独立身份与独立的版本线，
  不能合并成一个值。

## 幂等、更正与撤销的版本规则

* 消息原件按 `(来源, SHA-256 摘要)` 幂等：相同报文重送返回既有
  `message_id`，不新增任何观察或版本。
* 同一观察收到 F（最终）建立版本 1；收到 C（更正）追加新版本并把状态
  置为 `corrected`，旧版本原样保留；收到 D（撤销）追加状态为 D 的
  版本并把观察置为 `cancelled`，不删除行。撤销后再次收到 F 可重新生效。
* 库内对 `(观察, 消息)` 再加一道唯一约束，即使摘要逻辑被绕过，同一
  消息也无法对同一观察重复记账。

## 无法采用的值如何处理

类型化结果每个重复值带 `adopted` 与 `reason`：

* NM 内容不是合法数值、CE 缺少编码标识符：该值 `rejected`，观察隔离；
* OBX-2 是来源约定之外的未知类型：值 `unknown`，观察隔离，但原始 OBX
  段、组件与子组件原文随版本保留；
* 空字段（`empty`）与协议空值 `""`（`null`）区分记录，都是合法语义，
  不触发隔离；
* 单位（OBX-6）与参考范围（OBX-7）原样保存为 `unit_raw`/
  `reference_range_raw`，没有明确换算配置时不做任何单位换算。
